# SATYA AI Service — merged package

This folder merges the initial SATYA AI service with the additional retrieval,
generation, OCR, evaluation, and verification modules. It is designed to be
integrated with the SATYA Spring Boot backend.

## Current capabilities

- FastAPI internal service with `X-Internal-Token` authentication.
- PDF text extraction and paragraph segmentation.
- Reviewed-manifest ingestion into `data/evidence_bundle.json` and `data/index.json`.
- BM25 lexical retrieval, optional sentence-transformer semantic retrieval, hybrid
  reciprocal-rank fusion, and deterministic reranking.
- Optional OpenAI-compatible LLM drafting constrained to retrieved evidence IDs.
- Extractive fallback when LLM is disabled or unavailable.
- Exact source paragraph quotes in the response for Java canonical-store validation.
- Conservative potential-conflict flags and retrieval coverage heuristic.
- Optional OCR helper for scanned PDFs.

## Important limitations

This is an integration-ready development baseline, not a validated legal research
product. A retrieved paragraph or exact quote does not prove that a generated legal
interpretation is correct, current, or complete. Conflict detection is heuristic.
Human review of source documents, amendments, commencement dates, jurisdiction,
and extraction quality is required. The Java backend remains responsible for
checking every evidence ID and quote against its canonical evidence store.

## Setup (Windows PowerShell)

```powershell
py -3.11 -m venv .venv
.venv\\Scripts\\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
```

Set the environment variables from `.env` in your terminal/session (Python does
not automatically load `.env` in this package):

```powershell
$env:SATYA_INTERNAL_TOKEN = "your-long-random-secret-at-least-32-characters"
$env:SATYA_AI_DATA_DIR = "./data"
```

## Setup (macOS/Linux)

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
cp .env.example .env
export SATYA_INTERNAL_TOKEN='your-long-random-secret-at-least-32-characters'
export SATYA_AI_DATA_DIR='./data'
```

## Ingest official PDFs

Create a JSON manifest based on `manifest.example.json`, place PDFs relative to
the manifest, and run:

```bash
python scripts/ingest_pdfs.py --manifest path/to/manifest.json
```

Review the extracted `data/evidence_bundle.json` and `data/index.json` manually.
Only after reviewing the source text, page numbers, metadata and official URLs run:

```bash
python scripts/ingest_pdfs.py --manifest path/to/manifest.json --reviewed
```

The script requires 3–5 documents because the current Java evidence importer
expects that corpus size. Do not mark a corpus reviewed without actually reviewing it.

## Run service

```bash
uvicorn app.main:app --reload --port 8000
```

- Health: `GET http://localhost:8000/health`
- API docs: `http://localhost:8000/docs`
- Internal chat: `POST http://localhost:8000/internal/chat`

Example request body:

```json
{
  "schema_version": "satya-chat-v1",
  "question": "What does the source say about filing an application?",
  "corpus_revision": "your-corpus-revision"
}
```

Include header `X-Internal-Token` with the same secret configured in the Java backend.

## Optional semantic retrieval

```bash
pip install -r requirements-advanced.txt
```

Then set `SATYA_ENABLE_SEMANTIC=true`. The first model use may download model files
from Hugging Face and requires network access. Leave it disabled for a lightweight
BM25-only installation.

## Optional LLM generation

Set `SATYA_ENABLE_LLM=true`, `SATYA_LLM_API_KEY`, and (if needed) the compatible
provider URL/model. Install base requirements (httpx is included). LLM generation
is disabled by default. If it fails, the workflow falls back to extractive claims.
The model cannot introduce evidence IDs outside the retrieved passages. The Java
backend must still validate IDs and exact quotes.

## Optional OCR

Install `requirements-ocr.txt` and install the Tesseract and Poppler system
binaries separately. Then use `app.ingestion.ocr_loader.extract_scanned_pdf` from
your ingestion workflow. OCR output must be reviewed because it can misread legal text.

## Antigravity integration notes

1. Treat this directory as the single merged Python `ai-service` package.
2. Preserve the request/response contract in `app/schemas/chat.py` and the
   `/internal/chat` endpoint unless the Java `AiGateway` is updated in tandem.
3. Set identical `SATYA_INTERNAL_TOKEN` values in Java and Python environments.
4. Ensure Java canonical evidence records use the same paragraph IDs, corpus
   revision, and exact text generated by the ingestion bundle.
5. Run end-to-end tests with real reviewed documents before demoing legal answers.
